# Architecture and failure behavior

## Native apps and shared state

The Xcode project compiles shared Swift files into two separate native targets. UIKit owns touch capture on iPad; SwiftUI renders controls. The Mac companion uses public Core Graphics event posting, gated by macOS Accessibility. The Swift package compiles the same shared files into the host test library.

`PencilInterpreter` owns contact continuity, relative anchoring, tap/hold recognition, pressure activation, fitted active-area mapping, and the requirement to lift after cancellation or leaving the active area. `InputState` owns cursor position and the single held left-button state. The Mac is authoritative for button state. Easing pressure or lifting ends a drag or stroke. A new drawing stroke releases any previous stroke before moving to the new origin and pressing the button.

`MouseEventEncoder` constructs mouse and scroll events without posting, allowing actual AppKit decoding to be tested. The Mac keeps a private event source for its own button state, but obtains current keyboard modifiers from [`CGEventSource.flagsState(.combinedSessionState)`](https://developer.apple.com/documentation/coregraphics/cgeventsource/flagsstate(_:)). The installed SDK's `CGEventSource.h` documents the combined login-session table separately from private event state. Before posting, the encoder replaces the documented [keyboard modifier bits](https://developer.apple.com/documentation/coregraphics/cgeventflags) while preserving other event flags. One snapshot per input action keeps an instantaneous click's down/up pair consistent; each subsequent movement or release reads the current Mac state again. Command, Shift, Option, Control, Caps Lock, and Fn therefore are not latched for the lifetime of a drag or connection. No keyboard events are synthesized, no key content is captured, and no modifier state is accepted from the iPad. Permission guards and release attempts remain in `MouseOutput`; event construction alone cannot control the Mac.

Pencil input uses coalesced UIKit samples, without predicted samples or replaying late estimated-property corrections. Predicted coordinates cannot be reliably undone once committed into another app. Pointer movement and clicks accept only Pencil touches. The same UIKit surface separately tracks direct touches for two-finger scrolling; direct touches never become pointer or click input.

`TwoFingerScrollInterpreter` requires exactly two direct contacts and 4 points of centroid movement before activation. Finger identity/count changes reanchor the centroid without a jump. Fractional movement remains unrounded through recognition, velocity estimation, and transport. A separate 0.25×–4× scrolling sensitivity scales distance, without changing the activation threshold. Vertical and horizontal directions reverse independently; each initially inherits the former combined natural-scrolling preference. Pencil contact, cancellation, mode/geometry changes, settings changes, and disconnect reset scrolling; fingers remaining on the surface must all lift before a new gesture. Three or more direct contacts similarly block until all lift. Starting a scroll clears the Pencil double-click history. The Mac rejects scrolling while a mouse button is held.

`ScrollResponse` applies speed-dependent gain before user sensitivity and axis reversal. Raw centroid velocity is exponentially filtered with a 25 ms time constant; the interval-average velocity determines gain without delaying the movement itself. With speed `v` in iPad points/second, `u = max(0, v - 80) / 1000` and gain is `1 + 5u²/(1 + u²)`. Fine motion stays at 1×; fast swipes approach 6× gain while output speed continues growing. This is custom tuning, not Apple's undocumented trackpad curve. Finger changes, lifts, interruptions, and gaps over 100 ms reset the response. Equal timestamps use the current gain and accumulate travel for the next velocity estimate. The existing sensitivity multiplies the resulting distance, so changing sensitivity does not shift the acceleration thresholds. Momentum is calculated from the resulting scroll travel and is not accelerated a second time.

`ScrollMotion` coalesces contact updates at `CADisplayLink` cadence, requesting 60–120 Hz as the device permits. It derives release velocity from recent motion and emits separate contact and momentum phases. Momentum is exponentially damped, lasts at most 2 seconds, and stops on fresh finger/Pencil contact or any interruption. The former 2500 points/second launch ceiling is removed. Raw finger deltas retain a 2000-point per-axis sanity limit; scaled output uses a shared 16,384-point per-axis limit in the sender, receiver, and encoder so fast swipes at 4× sensitivity are not mistaken for invalid input. Momentum ends when both axes would move less than one point per display frame, avoiding a long tail of isolated integer-point steps. A final finger lifting within 80 ms of its partner can continue the same flick. A stationary pause before release suppresses momentum. A frame stall over 100 ms discards pending movement rather than replaying it. No additional finger-motion redraw is requested for the static surface.

`InputState` validates scroll-phase order and ends scrolling on pointer input, mode changes, or release. `ScrollEventEncoder` creates public Core Graphics continuous scroll events with explicit contact and momentum phases. It fills integer wheel-line, fractional fixed-point line, and integer point fields explicitly, preserving residual distance separately for the integer fields. This avoids the constructor's observed minimum of one integer wheel step for any nonzero pixel delta. The integer line fields are written first because they alter the other representations. Quartz's public point fields remain integer-valued; retaining fractional line data does not establish fractional pixel delivery to every receiving app. AppKit bridge tests verify deltas, flags, and phases without posting input. Apple's [point-field documentation](https://developer.apple.com/documentation/coregraphics/cgeventfield/scrollwheeleventpointdeltaaxis1) and [trackpad event guide](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/HandlingTouchEvents/HandlingTouchEvents.html) describe these field and phase distinctions. This is custom gesture recognition and deceleration; it is not a claim to reproduce Apple's private trackpad tuning exactly.

The optional Mac **Test Scrolling…** window measures delivery rather than only event construction. During an explicitly started recording, Styleus scroll events receive a numeric diagnostic tag; a local AppKit monitor records events delivered to that window, and a disposable WebKit page records its own wheel/scroll values. The recording is bounded to 60 seconds/20,000 rows and saved as `styleus-scroll-diagnostics.csv` in the user's temporary directory. It captures no keyboard events or external page content and installs no global monitor. `scripts/analyze_scroll_trace.py` compares tagged posted/received values and summarizes cadence. Recording can itself affect scheduling, so the native trackpad comparison uses the same instrumented page; these measurements are diagnostic rather than a controlled latency benchmark.

Prepared scroll events are posted at [`cgSessionEventTap`](https://developer.apple.com/documentation/coregraphics/cgeventtaplocation/cgsessioneventtap), after HID device filters, while retaining the existing Accessibility permission check. Development testing identified that a third-party HID scroll filter could transform prepared movement again at the HID stage, producing reversed discrete steps. Posting later avoids that particular device-filter transformation. This change affects only scroll delivery and does not modify other utilities' settings. Software filtering at later stages may still alter events; no universal utility compatibility is claimed. Event-count and per-tag differences must account for macOS coalescing before being interpreted as packet loss or distortion.

## Gesture and pressure activation

Trackpad contact anchors relative movement without pressing a button. A stationary lift generates a left click; two tap lifts within 350 ms and 24 iPad points generate click counts 1 and 2. Each tap emits exactly one mouse down/up pair. Holding for at least 500 ms and lifting generates one right click. Movement inside the existing 6-point radial tap allowance emits no pointer action, regardless of sensitivity, so a recognized tap cannot shift its target. The relative anchor still advances on every sample: ignored wobble is not accumulated or replayed. Once maximum excursion exceeds 6 iPad points, relative movement remains enabled for the rest of that contact, including a return inside the original allowance. That excursion disqualifies tap and hold recognition; pressure dragging also disqualifies any additional lift click. A firm stationary hold cannot become a drag. Absolute drawing positioning does not use this allowance.

Normalized UIKit force is `force / maximumPossibleForce`, clamped to 0–1; non-finite force becomes zero. The activation threshold defaults to 0.20 and is adjustable from 0.05 to 0.80. Release occurs at 70% of that threshold, providing hysteresis. Trackpad dragging additionally requires movement beyond tap tolerance. In drawing mode, light contact emits unpressed absolute positioning, activation emits stroke begin, and easing emits stroke end before unpressed movement. Repressing starts at the new location without a connecting line. The current pressure and threshold are drawn locally in UIKit, avoiding per-sample SwiftUI model publication.

The wire carries mouse actions plus display-only normalized pressure/contact/threshold metadata. Pressure activation changes button timing, not the receiving application's ink width; the metadata feeds only Styleus's optional Mac cursor indicator. No tilt or pressure-sensitive tablet input is delivered to receiving applications. Invalid coordinates cancel input, older sample timestamps are ignored, and cancellation clears tap history and blocks an existing contact until lift.

## Local iPad pressure feedback

The selected Minimal edge layout uses a noninteractive 28-point column at the left of the movement surface, inside the safe area. Its 14-point rail fills bottom to top, with a fixed activation cross-mark, blue pressure and orange held-input feedback. It replaces the earlier horizontal header. The current local gesture title is drawn in the movement surface without changing its bounds or hit testing. Numerical pressure is available to accessibility. No pulsing or smoothing animation is used.

`PencilFeedbackPresentation` reads the local interpreter’s contact, active and blocked state. Firm stationary trackpad contact remains Pointing; orange requires an actual local drag/stroke transition, including release hysteresis. Paused input clears pressure and held status. Cancellation, mode changes, resizing/rotation and leaving a drawing margin show Lift to resume when an existing contact is blocked. Lift returns to Ready. This is immediate local gesture feedback, not an acknowledgement that the Mac or receiving app applied an action.

`PencilFeedbackRelay` retains only the latest presentation and a weak UIKit view reference. `PencilInputView` updates it directly before dispatching actions, and also on configuration and interruption. The meter redraws only when the presentation changes or its bounds/appearance change. Samples do not publish through SwiftUI, change geometry, introduce timers or add network messages. Meter column width is fixed across states, so pressure changes cannot resize/cancel the input surface. Rotation still triggers the existing bounds-change cancellation. The former horizontal meters and redundant trackpad footer are removed.

## Compact controls and connection details

The header puts connection status beside Styleus, with an info-circle button that opens a native popover (sheet adaptation for compact presentation). `ViewThatFits` keeps the single landscape toolbar when it fits and moves controls to a second row when needed. The mode picker uses a menu; Disconnect remains visible. The transport selector and round-trip diagnostics live in Settings → Connection, with timing also available in the info popover.

`ConnectionProgress` records display-only typed stages and failures at existing networking callbacks. `ConnectionPresentation` supplies a short heading, original status text and relevant checks. Known permission, discovery, setup, version and session cases have distinct explanations; generic transport messages are preserved without inferring a cause. Retry/success/manual disconnect clears stale issues. This state never authorizes input or changes session/lease handling. Opening info or Settings calls the existing contact reset before presenting; mode changes and transport switching retain their existing cancellation paths.

## Optional cursor indicator

`PencilStatusRelay` piggybacks the latest status on immediate input packets. While connected, a separate 30 Hz timer sends a heartbeat only if status changed and no input packet has carried it within the last interval. This covers stationary pressure changes without queueing samples or delaying movement. The regular 200 ms heartbeat refreshes unchanged contact. UIKit reports status before each action; revision guards reject callbacks from an outdated surface. Mode/cancel messages and session reset clear it.

The Mac accepts status only after the same session, lease, sequence, geometry and Accessibility checks used for input. `CursorIndicatorState` rejects malformed pressure and expires unrefreshed contact after 450 ms. Orange uses the actual `InputState.leftHeld`, including drawing strokes; crossing the pressure threshold alone cannot make it orange. A stale pressure arc disappears, while an actual held button remains orange until release/watchdog. Every cancellation, mode/geometry change, disconnect, permission loss, lock/sleep and ordinary quit clears the indicator.

The indicator is a 48-point transparent, nonactivating AppKit panel with a 36-point ring, `ignoresMouseEvents`, and no key/main-window eligibility. It uses the panel’s native `CADisplayLink`, available at the existing macOS 14 minimum, to update in sync with the display containing the window. The requested rate follows available screen capabilities, including ProMotion; actual cadence remains system-controlled. A weak callback target avoids a retain cycle. The link is invalidated while hidden, and visible content is drawn within the frame callback. There is no independent 60 Hz timer, interpolation, global event monitor or additional permission. Its Cursor indicator preference remains available in the window and menu bar. The local-header update defaults the ring to Off and stores subsequent explicit choices under `optionalCursorIndicatorStyle`; the former default/legacy ring settings are not carried forward. Off hides the Mac overlay and starts no display link. Optional Dragging only requires actual held input, with no pressure animation or threshold tick; Pressure and dragging retains the blue pressure arc and white activation tick during contact. Off does not hide the local iPad meter. Screen edges may clip part of the ring. Multiple-display/full-screen/Spaces behavior needs physical verification.

`MouseOutput.post` returns the last destination it actually submitted, without changing event posting or modifier handling. The indicator keeps only the newest such position for the next display frame; it discards values older than 100 ms and clears pending positions when hidden/cancelled. No coordinate history is replayed. Quartz coordinates convert to AppKit using the primary screen’s frame, preserving negative origins and other displays. After consuming a destination, a frame without new Styleus movement reads `NSEvent.mouseLocation`, allowing local trackpad movement and OS adjustments to remain visible. This is presentation state only; it cannot move or hide the real cursor.

Apple documents [`NSCursor.current`](https://developer.apple.com/documentation/appkit/nscursor/current) as belonging to the application, potentially different from the visible cursor when another app is active. No supported public API was found for attaching a Styleus badge to the native cursor across unrelated applications. Apple recommends [view/window display links](https://developer.apple.com/videos/play/wwdc2023/10054/?time=1496) for display-synchronized drawing that follows movement between screens. The revised ring remains a separately composited window; these APIs do not guarantee that it appears in the same frame as the system cursor. Native cursor replacement, private APIs and cursor-hiding tricks are not used.

## Coordinates

Let the iPad surface be width W and height H, and let the Mac target have aspect ratio a = targetWidth / targetHeight. The fitted active width is min(W, H × a), with height activeWidth / a; both are centered in the surface. A contact inside that area is normalized to [0,1]² and mapped into the Mac target's global Quartz rectangle. Both coordinate systems use a top-left origin with positive Y downward. Negative display origins are retained, and the far edge is clipped just inside the selected rectangle.

Absolute mode uses only the selected display/region. Relative mode adds scaled motion to the current Mac cursor position and constrains it to the union of connected displays, choosing the nearest display boundary when a motion crosses a gap.

## Pairing and transport

The Mac generates a 32-byte secret using Security.framework. The pairing QR/text contains a format version, random pair identifier, and secret. Both apps store their credential in Keychain without iCloud synchronization. The iPad browses only the fixed `_styleus._tcp` service in `local.` and matches the paired service identity; TLS, not the advertised name, authenticates the endpoint.

Bonjour results can contain multiple interface types. The iPad requires an observed interface matching its selected connection mode and scopes a candidate service endpoint to each matching interface (at most four). Both modes constrain the actual connection type, keep discovery alive until the first authenticated Mac configuration, and validate the path before accepting state. The first valid configuration chooses the connection and closes the other candidates; selecting merely the first client TLS-ready callback could disagree with the Mac's admission order. Explicit scoping avoids the physically observed stall during unscoped wired resolution. Route loss/change closes the session rather than switching transport. Initial connection setup has a 15-second deadline per candidate, separate from the short input-safety deadlines below. The wire configuration uses version 7, adding explicit magnification phases and a receiver capability flag alongside Pencil status, scroll phases, click, absolute-positioning and pressure-drag semantics. Both apps must be updated together. Older envelopes can be decoded only to explain a version mismatch and never authorize input.

Network.framework is configured for TLS 1.2 and PSK/AES-128-GCM. The client requires the selected wired or Wi-Fi interface. The Mac listener accepts local-link peers, prohibits cellular/other/loopback types, disables peer-to-peer inclusion, and checks each authenticated connection's route. There is no public-host input, plaintext fallback, port mapping, relay, or cloud dependency. Only one authenticated client is admitted; pending unauthenticated handshakes are bounded and timed out. This prevents unauthorized control, not denial of service by a hostile local network.

The default wired choice uses the public IP network interface exposed by USB device connectivity. It adds no driver, USB multiplexer dependency, or privileged helper. Network.framework identifies a wired interface, not a physical cable or connector; actual USB behavior is therefore a separate hardware acceptance check. See [the transport decision](adr/0002-selectable-wired-transport.md).

Frames have a four-byte network-order length and a bounded JSON body. Malformed or oversized frames close the connection. Outgoing queues are bounded to 64 frames and expire after 500 ms; they are discarded on close.

## Session freshness

The Mac creates a new random session ID at each authenticated connection. Every 200 ms it issues an unpredictable input lease, valid for 750 ms according to the Mac's monotonic clock. Each input packet carries the session, lease, geometry revision, and increasing sequence number. The receiver rejects duplicates, expired leases, prior sessions, and prior geometry revisions. This avoids trusting synchronized wall clocks or sender timestamps.

The iPad sends heartbeats every 200 ms, plus bounded changed-status updates for the optional indicator. The Mac releases input and closes after one second without valid input/heartbeat; the iPad closes if it has not received fresh state for 750 ms. Timers run in the common run-loop modes, including while UI controls track. These are scheduling targets, not measured hard-real-time guarantees.

Timing probes carry the current session ID and a random nonce. The Mac echoes a probe only for the current non-expired session, without accepting input, renewing a lease, or advancing its watchdog. The iPad measures elapsed time using its own monotonic clock, allows one outstanding probe, rejects mismatched/duplicate/expired replies, and keeps the latest 20 valid samples. These app-to-app round trips include scheduling and queue time; they do not measure UIKit sampling, CGEvent delivery, or display rendering end to end. No timing history survives a disconnect.

## Interruptions

Mode, pressure/scroll-setting, geometry, and bounds changes invalidate active contacts and release held input. Selecting a custom region stops the listener until the selection finishes so remote pointer input cannot manipulate the selection overlay. New display geometry revokes existing leases immediately.

The iPad disconnects when its scene becomes inactive, including system interruptions. The Mac stops on ordinary quit, screen/system sleep, session deactivation, and lock. The Mac intentionally does not stop merely because another Mac app becomes foreground. Network close callbacks and watchdogs release held input. No input queue or held state persists across reconnection.

The Mac's in-process watchdog cannot run after a forced termination or OS failure. Normal quit and network failures have explicit release paths; physical fallback remains necessary after a process crash.

## Scope boundaries

Basic mouse drawing does not produce pressure-sensitive tablet events. The current targets are paper annotation in Zotero and secondary Notability use. Drivers, privileged helpers, paid dependencies, modification of Zotero, and universal tablet emulation require a separate scope decision. [Pressure investigation](pressure-support.md)

## Experimental native zoom

The iPad setting defaults to off. When enabled and advertised as available by the Mac, a shared two-finger interpreter chooses scrolling from centroid movement or pinching from span change. The chosen action remains exclusive for that pair. Pinch sends incremental distance ratios as began/changed/ended/cancelled samples with no momentum. Pencil contact and interruptions cancel zoom, and remaining contacts must lift before a new gesture. With zoom disabled, touch updates delegate to the existing scrolling interpreter.

The receiver requires a begin phase, validates finite bounded increments and rejects zoom while a mouse button is held. Other input cancels zoom first. Existing session, lease, sequence, geometry and watchdog checks apply unchanged. Foreground-app changes release receiver zoom state; output drops later updates and attempts cancellation only to the original process.

The Mac's original Swift encoder uses generic Core Graphics setters with undocumented gesture fields documented in Apple WebKit test sources. It verifies AppKit type/phase/fractional-value readback at runtime and advertises availability only after that check. Magnification uses the session event stream, with an anchor captured at begin and no inherited keyboard modifiers. No Hammerspoon code, helper, virtual driver or network service was added. Source attribution is included in both app bundles. These checks cannot establish application compatibility; the native diagnostic and physical hardware checklist are separate validation steps.
